# TripShare payable mirror, debt-only policy
Consumption remains entirely in the existing bill-date TripShare consumption projection. Neither payment nor Undo inserts/deletes a transaction. Four additive mirror tables use owner/connection/space/bill/member/direction identity; recipient legs are separate. Payment allocation cache is unnecessary because the source exports canonical reconciled debt rows; it is omitted. Full current snapshots are bounded (5000 legs/1.9MB imported JSON), validated and atomically applied under fenced leases. Rows disappear on deletion and return on restoration. Paid history is excluded on first import; known rows can transition to Paid. Replays are upserts. Per-currency source units retained, including IDR zero-decimal source units. No conversion or balancing adjustment.
First import and scope changes require a version-matched preview confirmation. Unconfirmed enabled memberships block import. Missing/duplicate source identities or amount mismatches fail closed, retain last good data and display an error. Source service notification can run only already-activated connections. A page opening performs a reconciliation; a manual retry is available. Source delivery errors remain in the durable source outbox and retry on subsequent requests, with three bounded immediate attempts per dispatch. There is no independent always-on scheduler while both apps are unused. Endpoint is owner-bound, same-origin user actions only, platform service access plus application token for notifications; no client secret. Synced rows are read-only and link back to TripShare.
Pre-release local QA Test exercised the real TripShare projection→Pocket SQLite engine across add/edit/partial/full/two Undo/delete/restore/three replays, and checked unchanged consumption. Unit/security/regression suites and types/build checked before release. Actual live QA follows rollout. All real financial groups stay read-only. First real import is left for the user to approve.
